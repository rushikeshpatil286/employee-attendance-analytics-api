# REVIEW.md

Defects found in the starter `app/main.py`. Every row was reproduced or confirmed by reading the code; all are fixed in the current file.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Grace test is `int(minutes) > 10`, so the seconds are lost: 09:40:01 is 10 min 1 s, `int` gives 10, and 10 > 10 is false, so a late punch-in reports 0. | Shift 09:30, punch-in 09:40:01: expected 10, got 0. | Work in whole seconds: late only if `seconds > 600`, then `seconds // 60` (R2). |
| 2 | `compute_late_minutes` | Shift start is built with `punch_in.replace(hour=..)` on the punch's own (local/naive) date and zone, not the IST attendance date. Breaks for overnight shifts (punch 00:30 is compared with 22:00 *today*, giving a large negative number, i.e. 0) and when the server is not in IST. | Overnight shift 22:00, punch-in 00:30 IST: expected 150, got 0. | Shift start is `attendance date + shift_start` in IST (`shift_start_at`); the date comes from R1. |
| 3 | `compute_work_hours` | Python `round()` is banker's rounding on a float; R4 wants half-up. Also seconds are not truncated first. | 8 h 00 m 18 s = 8.005 h: expected 8.01, got 8.0. | Integer arithmetic `(seconds*100 + 1800) // 3600 / 100` on second-truncated times. |
| 4 | `compute_overtime` | Returns any positive minutes: the 30-minute minimum (R3) is missing, so 5 minutes of overtime is reported. The shift end uses the record's date with no next-day shift for overnight shifts, and `.replace(tzinfo=IST)` is applied to a naive date. | Shift end 18:30, punch-out 18:40: expected 0, got 10. Overnight 22:00-06:00 punch-out 06:40: expected 40, got a negative number (clamped to 0). | `shift_end_at` adds a day for overnight shifts; overtime counts only when floor-minutes >= 30. |
| 5 | `EmployeeIn` / `create_employee` | No validation at all: `emp_code` format, e-mail, lengths, `HH:MM` shape, `shift_start == shift_end`, `joined_on` being a real date. Bad input is stored. | POST `shift_start: "25:99"`, `joined_on: "2026-02-30"`, `emp_code: "abc"`: all 201 instead of 422. | Pydantic constraints from the contract (`Field(pattern=..)`, a date validator, a model validator for shifts). |
| 6 | `create_employee` | Check-then-insert race and no unique index: parallel creates can all pass `find_one`. | 10 simultaneous POSTs with the same `emp_code`: several 201s, duplicate documents. | Unique index on `emp_code`, `insert_one` and catch `DuplicateKeyError` -> 409. |
| 7 | `create_employee` | `created_at = datetime.now()` is a naive *local* time (stored as if it were UTC) and the response returns a datetime string, not epoch ms. | `created_at` off by the server's UTC offset; response field is an ISO string. | UTC-aware `now_dt()` stored; `employee_out` converts to epoch ms. |
| 8 | `list_employees` | `skip = page * page_size` skips a whole page (page 1 starts at item 21). `total` ignores the department filter (`count_documents({})`). No sort. | 9 | `punch_in` | Unknown employee: `emp` is `None` and `emp["shift_start"]` raises `TypeError`, a 500 instead of 404. | POST punch-in for a non-existent `emp_code`. | `get_employee` raises 404 first. |
| 10 | `punch_in` | Timestamp handling: `datetime.fromtimestamp(ms/1000)` is local-time and naive; `if body.punched_at` treats 0 as "missing"; no range check; floats/strings are coerced by `Optional[int]`; seconds not truncated. The attendance date comes from the local date, with no IST and no overnight rule (R1). | `punched_at` 1783312500 (seconds) accepted; server in UTC puts a 02:00 IST punch-in on the previous date. | `StrictInt` with `100_000_000_000 <= v <= 4_102_444_800_000`; UTC-aware conversion, truncated to seconds; `attendance_date()` implements R1. |
| 11 | `punch_in` | Check-then-insert race, no unique index: two simultaneous punch-ins both pass `find_one` and both insert. | Two parallel punch-ins: two 201s and two documents for one (emp, date). | Unique `(emp_code, date)` index; the insert decides the winner, `DuplicateKeyError` -> 409. |
| 12 | `PunchInIn.status` / `punch_in` | `status` is any string; `ABSENT`, `LEAVE` or `"banana"` are stored. | `status: "ABSENT"` -> 201. | `Literal["PRESENT","WFH","ON_DUTY"]` -> 422. |
| 13 | `punch_in` response | Returns an `id` (the ObjectId as a string) and raw datetimes: `_id` must never be exposed, instants must be epoch ms. | Response has `"id"` and ISO strings for `punch_in`. | `record_out` builds the exact `AttendanceRecord` shape. |
| 14 | `list_attendance` | Loads the whole collection into memory, sorts in Python and slices. At 100k documents this is slow and memory-heavy. Sort has no `emp_code` tie-break (the sort is by `date` only; ties order arbitrarily). | `/attendance` on 100k records takes seconds; page order changes between calls for the same date. | Query in MongoDB with `sort(date desc, emp_code asc).skip().limit()` backed by an index of the same shape. |

| 17 | module level | `MongoClient(...)` is naive-datetime by default (`tz_aware` off) and nothing creates indexes, so every query is a collection scan and the uniqueness guarantees above do not exist. | Naive datetimes need ad-hoc handling; explain shows `COLLSCAN`. | `tz_aware=True`; `create_indexes()` runs idempotently at startup (lifespan). |

## Looked at and judged not a defect

* `load_dotenv()` with its default `override=False`: variables already set in the real environment win over `.env`, which is exactly what the contract asks for.
* `doc.pop("_id", None)` after `insert_one`: it is needed because PyMongo adds `_id` to the dict; it was right to remove it (the response is rebuilt explicitly now anyway).
* `list_attendance` `$gte` / `$lte` on `date` strings: correct and inclusive, because `YYYY-MM-DD` sorts lexicographically in date order.
* Defaults `shift_start="09:30"`, `shift_end="18:30"`: match the contract.
* Sync `def` endpoints with the synchronous `MongoClient`: FastAPI runs them in a thread pool, which is fine for this workload; I kept it rather than rewriting to async.
